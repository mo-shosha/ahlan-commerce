# Query Contract

Named SQL files under `db/queries/products/`. File names and query names are fixed so mentor
reviews are consistent. Cornucopia generates one Rust function per query, named after it.

## Product Row Return Shape

Every query that returns a product row returns these fields:

`id`, `title`, `handle`, `description`, `price_cents`, `inventory_quantity`, `published`,
`published_at`, `created_at`, `updated_at`

`description` and `published_at` are nullable (`?` in the Cornucopia annotation).

## Queries

| File | Query name | Parameters | Returns | Ordering |
| --- | --- | --- | --- | --- |
| `db/queries/products/create_product.sql` | `create_product` | `id`, `title`, `handle`, `description`, `price_cents`, `inventory_quantity`, `published`, `published_at`, `created_at`, `updated_at` | product row | - |
| `db/queries/products/list_products.sql` | `list_products` | none | product rows | `created_at asc, id asc` |
| `db/queries/products/list_published_products.sql` | `list_published_products` | none | product rows where `published = true` | `published_at desc nulls last, created_at asc, id asc` |
| `db/queries/products/update_product_publication.sql` | `update_product_publication` | `id`, `published`, `published_at`, `updated_at` | product row | - |

## Rules

`create_product`:

- `id` is generated by Rust as UUIDv7 before calling the query.
- `created_at` and `updated_at` are passed from the application clock.
- `published_at` is passed as a timestamp when `published = true`, otherwise null.

`update_product_publication`:

- Set `published` to the input value.
- Set `published_at` to the input value.
- Set `updated_at` from the application clock.

The rules are applied in Rust (`packages/catalog`), not in SQL. The queries store exactly
what they are given.

## Done Check

- Cornucopia-generated bindings expose these query names:
  `db_generated::queries::products::{create_product, list_products, list_published_products, update_product_publication}`.
- The DAL (`packages/db/src/products.rs`) wraps those generated calls. Handlers never call
  generated query functions.
